# Часть I. Введение и философия среды

## Глава 1. Миссия и архитектурная концепция PyScribe

**PyScribe IDE** — это специализированная среда разработки и статического анализа программного обеспечения, созданная для того, чтобы преодолеть разрыв между обычным редактированием кода и глубоким пониманием архитектуры проекта.

В большинстве современных редакторов разработчик видит лишь плоский набор текстовых файлов. PyScribe меняет этот подход: каждый файл, класс, метод и зависимость воспринимаются средой как взаимосвязанные элементы единой системы.

```
┌─────────────────────────────────────────────────────────────┐
│                    PyScribe IDE Core                        │
├──────────────────────────────┬──────────────────────────────┤
│      Code Crafting Layer     │   Project Intelligence Layer │
│  • Редактор QCodeEditor      │  • Статический аудит AST     │
│  • PEP 8 Форматирование      │  • Граф связей зависимостей  │
│  • Генерация Docstrings      │  • Анализ зоны поражения     │
│  • Встроенный терминал       │  • Архитектурный паспорт     │
└──────────────────────────────┴──────────────────────────────┘
```

### Ключевые принципы PyScribe:
1. **Автономность и скорость**: среда запускается мгновенно, не перегружена лишними фоновыми службами и может работать полностью автономно.
2. **Прозрачность архитектуры**: показатели здоровья кода (Health Index), цикломатическая сложность и зависимости визуализируются непосредственно во время работы.
3. **Безопасность разработки**: система предупреждает о потенциальных регрессиях до того, как код попадёт в систему контроля версий.
4. **Сквозной контроль изменений**: комбинация встроенного Git, облачного GitHub-модуля и локальной «Капсулы изменений».

### Основные компоненты рабочей области:
- **Панель меню (Menu Bar)**: расположена в верхней строке окна. Предоставляет доступ ко всем операциям над файлами, проектными метаданными, консолью и справочными материалами.
- **Activity Bar (Левый неоновый док)**: вертикальная инструментальная панель для быстрого переключения между режимами:
  - `📁 Проводник`: дерево файлов текущего проекта.
  - `🔍 Поиск`: полнотекстовый поиск с учётом регулярных выражений.
  - `▷ Запуск и отладка`: конфигурации запуска и аргументы командной строки.
  - `🌿 Контроль версий Git`: ветки, индексация и синхронизация.
  - `⚡ Анализатор проектов (Intelligence)`: комплексный дашборд здоровья и метрик.
  - `⚙ Параметры`: настройки среды и внешнего вида.
- **Вкладочная область редакторов (Tabs Hub)**: поддерживает одновременное открытие десятков файлов, разделение экрана (Split View) и специализированные вьюеры.
- **Нижний статус-бар редактора**: показывает номер строки, номер столбца, индикатор фоновых процессов (Busy Spinner) и кнопки быстрых трансформаций кода.
- **Нижняя панель терминала**: встроенная консоль операционной системы с поддержкой потокового вывода и истории команд.

## Глава 3. Быстрый старт: от открытия папки до первого запуска

### Шаг 1. Открытие рабочей папки
Для начала работы откройте каталог с вашим исходным кодом одним из способов:
- Нажмите комбинацию клавиш **`Ctrl + O`**.
- В верхнем меню выберите пункт **`Файл` → `Открыть папку…`**.
- При запуске в стартовом окне выберите проект из списка последних или нажмите **«Открыть каталог»**.

> **Важно:** Как только проект открыт, PyScribe автоматически инициирует фоновый индекс файлов и обновляет аналитический дашборд. Название текущего открытого проекта всегда отображается в заголовке окна и в шапке проводника.

### Шаг 2. Навигация и редактирование
В левой панели проводника раскройте нужную папку и кликните на файл для открытия. Вы можете создавать новые файлы прямо из контекстного меню проводника или по нажатию **`Ctrl + N`**.

### Шаг 3. Исполнение и проверка
Для запуска исполняемого файла нажмите клавишу **`F5`** либо зеленую кнопку запуска на верхней панели. Результат вывода немедленно отобразится во встроенном терминале.

# Часть II. Редактор кода QCodeEditor

## Глава 4. Возможности ядра редактора: подсветка, отступы и масштабирование

Ядром среды является специализированный редактор **QCodeEditor**, спроектированный с акцентом на высокую скорость отрисовки и интеллектуальную помощь разработчику.

### Масштабирование шрифта «на лету»
В PyScribe внедрён механизм синхронного динамического масштабирования:
- **`Ctrl` + `+`** (или `Ctrl` + `=`): Увеличение размера шрифта на 1 pt.
- **`Ctrl` + `-`**: Уменьшение размера шрифта на 1 pt.
- **`Ctrl` + `0`**: Мгновенный сброс кегля к стандартному значению (13 pt).

> **Техническая особенность:** Масштабирование пересчитывает базовый размер шрифта всего редактора. Это гарантирует, что уже набранный текст, вновь вводимые символы и вставляемый из буфера фрагмент имеют строго одинаковый визуальный размер без рассогласования курсора.

### Автоматические отступы и скобки
- Автоматический отступ при переходе на новую строку после двоеточия (`:`) в Python или фигурной скобки (`{`) в языках семейств C/C++/C#/JavaScript.
- Автоматическое закрытие парных символов: `( )`, `[ ]`, `{ }`, `" "`, `' '`.
- Подсветка парных скобок при нахождении курсора рядом с ними.

## Глава 5. Навигация, интеллектуальный поиск и замена

### Быстрый переход по строкам
Для перехода к произвольной строке кода нажмите **`Ctrl + G`**. Появится модальное окно ввода: укажите номер строки (например, `142`), и курсор мгновенно переместится в целевую позицию с автоматическим центрированием экрана.

### Поиск и замена в файле
- **`Ctrl + F`** — открывает аккуратную панель поиска в нижней части редактора.
  - Поддерживается поиск с учётом регистра (`Match Case`).
  - Поиск только целых слов (`Whole Words`).
  - Поиск по регулярным выражениям (`Regex`).
  - Кнопки `Найти далее` (Enter) и `Найти ранее` (Shift+Enter).
- **`Ctrl + H`** — переключает панель в режим пакетной замены.
  - Построчная замена текущего совпадения.
  - Пакетная замена всех вхождений в документе одним нажатием (`Заменить всё`).

### Сквозной поиск по проекту
Переключитесь на вкладку `🔍 Поиск` в Activity Bar или нажмите **`Ctrl + Shift + F`**. Введите ключевое слово или регулярное выражение. В результатах отобразится список всех файлов с номерами строк и контекстом найденных фрагментов. Двойной клик по результату открывает файл на нужной строке.

## Глава 6. Автоматизация: PEP 8 форматирование и автодокументирование

В нижней строке каждого открытого редактора расположены две функциональные кнопки:

```
[Ln 28, Col 14]       [ ⟳ Анализ ]       [ Форматирование ]  [ Автодокументирование ]
```

### 1. Кнопка «Форматирование»
Выполняет автоматическую нормализацию исходного кода:
- Приведение длины строк и интервалов к стандарту PEP 8.
- Удаление висячих пробелов в концах строк (trailing whitespace).
- Коррекция отступов вокруг операторов присваивания и сравнения.
- Обеспечение пустой строки в конце файла.

### 2. Кнопка «Автодокументирование»
Анализирует синтаксическое дерево (AST) текущего файла и находит функции, методы и классы, лишённые документации:
- Генерирует стандартный блок `docstring` в стиле Google / Sphinx.
- Извлекает имена аргументов, их предполагаемые типы из type hints.
- Формирует секции `Args:` и `Returns:`.
- Автоматически вставляет сформированный блок непосредственно под сигнатуру метода.

## Глава 7. Интерактивная линза кода (CodeLens) и мини-карта

### Что такое CodeLens?
Прямо над заголовками функций и классов в редакторе отображаются интерактивные полупрозрачные аннотации:
- Количество ссылок и вызовов метода в рамках проекта.
- Наличие ассоциированных модульных тестов (`▶ Запустить тесты`).
- Уровень сложности метода (`Сложность: 3 (Низкая)`).

Клик по аннотации открывает список мест использования символа или переходит к определению.

# Часть III. Аналитическая система Project Intelligence

## Глава 8. Комплексный аудит кодовой базы и здоровье проекта

Вкладка **Project Intelligence** (вызывается кликом по значку молнии `⚡` в Activity Bar) представляет собой встроенный аналитический центр архитектора ПО.

```
┌────────────────────────────────────────────────────────────────────────┐
│                        PROJECT INTELLIGENCE                            │
├────────────────────────────────┬───────────────────────────────────────┤
│    ИНДЕКС ЗДОРОВЬЯ ПРОЕКТА     │       КЛЮЧЕВЫЕ ПОКАЗАТЕЛИ             │
│                                │                                       │
│          ╭────────╮            │  • Файлов: 24                         │
│        ╱   94%    ╲           │  • Строк кода (LOC): 3 420            │
│       │  ОТЛИЧНО  │            │  • Функций / методов: 118             │
│        ╲          ╱            │  • Классов: 16                        │
│          ╰────────╯            │  • Средняя сложность: Низкая (2.4)    │
├────────────────────────────────┴───────────────────────────────────────┤
│  БЫСТРЫЕ ДЕЙСТВИЯ:                                                     │
│  [ Архитектурный паспорт ]  [ Интерактивный граф ]  [ Рекомендации ]   │
└────────────────────────────────────────────────────────────────────────┘
```

### Что анализатор пропускает

Анализ выполняется в фоновом потоке и **не спускается** в каталоги, которые не содержат исходного кода проекта. Это то, что позволяет открывать крупные проекты за секунды вместо минут:

- системы контроля версий: `.git`, `.hg`, `.svn`;
- окружения и кеши Python: `venv`, `.venv`, `env`, `__pycache__`, `.mypy_cache`, `.pytest_cache`, `.tox`;
- зависимости: `node_modules`, `site-packages`, `bower_components`, `vendor`, `third_party`, `packages`;
- результаты сборки: `dist`, `build`, `out`, `obj`, `bin`, `target`, `coverage`, `installer_output`, `Debug`, `Release`, `artifacts`, `publish`;
- служебные каталоги IDE и логи.

Дополнительно:

- файлы генерированного и минифицированного кода (`*.min.js`, `*.map`, `*.bundle.js`, lock-файлы) не разбираются;
- файлы крупнее **512 КБ** пропускаются — это обычно сгенерированные данные;
- соблюдается **`.gitignore`** проекта, а собственные правила можно добавить в **`.pyscribeignore`** (по одному шаблону на строку);
- если исходников больше **4000**, анализ останавливается на лимите, а в панели появляется предупреждение `SCAN_LIMIT`;
- файл, на котором парсер срывается (например, патологическая вложенность), пропускается с пометкой `PARSE_SKIPPED`, а не прерывает весь анализ.

Сколько каталогов и файлов было пропущено и **какие именно**, видно в подсказке к строке «Проверено файлов: N за M мс».

Те же правила действуют для индекса автодополнения, быстрого открытия (`Ctrl + P`), поиска по проекту и контекста ИИ-агента — поэтому все эти функции одинаково быстро работают на больших репозиториях.

**Интерфейс не блокируется.** Анализ выполняется в отдельном потоке, а индекс автодополнения строится порциями по 40 файлов за такт цикла событий: окно остаётся отзывчивым даже на проекте из десятков тысяч файлов.

### Радиальный индикатор здоровья (Health Gauge):
- Отображает точное математическое значение качества архитектуры от **0 до 100%**.
- Заменяет устаревшие субъективные буквенные оценки на прозрачный расчёт.
- Цветовая индикация:
  - `90% – 100%` (Неоновый зеленый `#2EA043`): Идеальная модульность, чистый код.
  - `75% – 89%` (Мягкий бирюзовый `#58A6FF`): Хорошая структура, минимальные замечания.
  - `50% – 74%` (Янтарный `#D29922`): Требуется рефакторинг отдельных компонентов.
  - `0% – 49%` (Алый `#F85149`): Высокий риск деградации, сильная связность.

## Глава 9. Метрики исходного кода и цикломатическая сложность

Система Project Intelligence собирает следующие показатели:

| Метрика | Значение | Интерпретация |
| :--- | :--- | :--- |
| **LOC (Lines of Code)** | Общее число строк | Масштаб проекта и физический объём кода. |
| **SLOC (Source LOC)** | Значимые строки | Строки без учёта пустых строк и комментариев. |
| **Cyclomatic Complexity (CC)** | Цикломатическая сложность Маккейба | Число линейно независимых путей исполнения через код. Норма: < 10 на метод. |
| **Maintainability Index (MI)** | Индекс сопровождаемости | Оценка простоты внесения изменений в процентах (0–100%). |
| **Степень связности (Coupling)** | Афферентные / эфферентные связи | Измерение зависимостей между подсистемами. |

## Глава 11. Анализатор зоны влияния правок (Impact Analyzer)

Вкладка **«Влияние правок»** решает критическую проблему архитектурного проектирования:
> *«Что произойдёт с остальной системой, если я изменю или удалю этот файл?»*

### Порядок работы:
1. Выберите интересующий файл в выпадающем списке модуля.
2. Impact Analyzer мгновенно сканирует дерево графа и выводит:
   - **Прямые зависимые компоненты**: модули, которые напрямую импортируют выбранный файл.
   - **Транзитивные риски**: компоненты верхнего уровня, использующие результат работы этих модулей.
   - **Критичность изменения**: процент всей кодовой базы, потенциально затрагиваемый правкой.

## Глава 13. Управление локальным репозиторием Git

Панель **Git** (вызывается значком ветки `🌿` в Activity Bar) объединяет в себе полноценный клиент системы контроля версий.

```
┌────────────────────────────────────────────────────────────────────────┐
│  КОНТРОЛЬ ВЕРСИЙ (GIT)                                                 │
├────────────────────────────────────────────────────────────────────────┤
│  Текущая ветка: [ main ▾ ]                                             │
│                                                                        │
│  ИЗМЕНЕНИЯ (3 файла):                                                  │
│  [M]  app/main_window.py                                               │
│  [M]  widgets/GitPanel.py                                              │
│  [?]  new_feature.py                                                   │
├────────────────────────────────────────────────────────────────────────┤
│  Сообщение коммита:                                                    │
│  ┌──────────────────────────────────────────────────────────────────┐  │
│  │ feat: add explicit notification dialogs for git actions          │  │
│  └──────────────────────────────────────────────────────────────────┘  │
│  [ Зафиксировать (Commit) ]    [ Синхронизация ]   [ Push ]   [ Pull ] │
└────────────────────────────────────────────────────────────────────────┘
```

### Основные операции:
1. **Индексация (Staging)**:
   - Кнопка `+` рядом с файлом или пункт меню «Индексировать все изменения».
2. **Создание коммита (Commit)**:
   - Введите пояснительный текст в поле сообщения и нажмите кнопку **«Зафиксировать»**.
   - PyScribe проверяет наличие изменений. При успешной фиксации появляется наглядное модальное уведомление с хешем коммита и статусом операции.
3. **Переключение и создание веток**:
   - Клик по кнопке текущей ветки открывает меню со списком локальных веток и пунктом `Создать ветку…`.

## Глава 14. Облачная интеграция с GitHub: PAT, Push, Pull и публикация

PyScribe поддерживает прямую интеграцию с облачным сервисом **GitHub**:

### 1. Авторизация через Personal Access Token (PAT)
- В верхнем меню выберите **`Git` → `Аккаунт GitHub (Авторизация PAT)…`**.
- Введите токен доступа GitHub (требуемые права: `repo`, `read:user`).
- После авторизации среда отобразит ваш аватар, логин и статус подключения.

### 2. Получение (Pull) и отправка (Push) изменений
- Кнопка **`Получить (Pull)`**: безопасно скачивает и сливает удалённые коммиты из ветки `origin`. По завершении выводится подробный отчёт об успехе или предупреждение о конфликтах.
- Кнопка **`Отправить (Push)`**: передаёт ваши зафиксированные локальные коммиты на сервер. Среда отображает статус отправки и обновляет указатель ветки.

### 3. Публикация нового проекта в один клик
Если ваш локальный проект ещё не связан с GitHub:
- Нажмите кнопку **«Опубликовать проект на GitHub»**.
- Задайте имя удалённого репозитория, описание и тип видимости (*Public* / *Private*).
- PyScribe автоматически создаст репозиторий на вашем аккаунте через GitHub API, настроит remote `origin` и выполнит первичный push ветки `main`.

## Глава 15. Локальная «Капсула изменений»: история и откат без Git

**Капсула изменений** — уникальный механизм непрерывной защиты кода, работающий локально даже без настроенного репозитория Git.

- При каждом сохранении файла среда делает локальный инкрементальный снимок.
- Меню **`Git` → `Капсула изменений (История)`** открывает диалоговое окно истории снимков.
- Вы можете выбрать любой предыдущий момент времени (например, 20 минут назад), просмотреть визуальный diff (разницу строк) и восстановить состояние файла в один клик.

### Оболочки и режимы

Терминал запускает настоящую оболочку, а не эмулятор:

| Оболочка | Как выбрать | Особенности |
| :--- | :--- | :--- |

## Глава 17. Специализированные просмотрщики: таблицы, PDF, Markdown и Hex-дамп

PyScribe из коробки включает производительные вьюеры для форматов, сопровождающих разработку:

### 1. Просмотрщик таблиц (Table Viewer — .csv, .tsv, .xlsx, .xlsm)
- **Высокая производительность**: виртуальная модель `QAbstractTableModel` мгновенно открывает и плавно прокручивает наборы данных из более чем 100 000 строк без зависаний.
- **Поддержка форматов**: CSV (любые разделители), TSV, Excel (`.xlsx`, `.xlsm` с многостраничными книгами и переключением листов вкладками снизу).
- **Живой поиск и фильтрация**: поле поиска с мгновенной фильтрацией строк и счётчиком совпадений.
- **Умная сортировка**: клик по заголовку столбца сортирует данные с автоматическим определением чисел (9 перед 25 и 100), дат и текстовых строк.
- **Гибкость параметров**: переключение разделителя (авто, запятая, точка с запятой, табуляция, pipe), выбор кодировки (UTF-8, Windows-1251, CP866, Latin-1) и переключатель первой строки как заголовков.
- **Статистика в реальном времени**: при выделении ячеек в строке состояния мгновенно рассчитываются количество, сумма, среднее, минимум и максимум для числовых значений.
- **Копирование и экспорт**: копирование ячеек в форматах TSV (для Excel / Google Таблиц), CSV или строк целиком, а также экспорт в `.csv` и `.json`. Кнопка «Открыть как текст» позволяет в один клик переключиться в обычный редактор кода.

### 2. PDF Viewer (.pdf)
- Позволяет читать архитектурные схемы, ТЗ, книги и научные статьи непосредственно во вкладках IDE.
- **Интерактивное оглавление (TOC)**: кнопка `☰` на панели открывает боковое дерево закладок документа с главами и подразделами для мгновенного перехода по клику.
- **Извлечение и копирование текста**: кнопка `📄` открывает диалог просмотра извлечённого текста страницы, а контекстное меню позволяет скопировать текст в буфер обмена в один клик.
- **Поддержка паролей**: защищённые шифрованием PDF-документы запрашивают пароль при открытии.
- **Ночной режим (инверсия цветов)**: кнопка `🌓` инвертирует цвета страниц для комфортного чтения в тёмное время суток.
- **Настоящий масштаб**: страница живёт в прокручиваемой области, поэтому 25–400 % меняют её размер на экране, колесо мыши с `Ctrl` зумит.
- **Вписывание**: `По ширине` (Ctrl+1) и `Вся страница` (Ctrl+0); при изменении окна режим пересчитывается автоматически. Двойной щелчок переключает «по ширине» ↔ 100 %.
- **Навигация**: поле номера страницы, кнопки «в начало/назад/вперёд/в конец», клавиши `Home`/`End`, `Page Up`/`Page Down`, а также быстрый переход по `Ctrl+G`.
- **Поворот** страницы на 90° кнопкой ⟳ или `Ctrl+R`.
- **Поиск по всему документу**: поле «Найти в PDF…» (`Ctrl+F`), найденные страницы, подсветка совпадений жёлтым и переходы между ними стрелками ▴/▾.
- **Экспорт**: возможность сохранения страницы как изображения PNG через контекстное меню.

### 3. Шестнадцатеричный вьюер и инспектор данных (Hex Viewer)
- **Виртуальная архитектура**: мгновенное открытие файлов любого размера (включая дампы памяти и прошивки в сотни мегабайт) с 16-байтным выравниванием и параллельным отображением смещений, HEX и ASCII.
- **Инспектор данных (Data Inspector)**: интерактивная боковая панель с поддержкой порядка байтов Little Endian / Big Endian:
  - 8-битное двоичное представление (`01001101`);
  - знаковый и беззнаковый Int8 / UInt8;
  - 16-битные целые (Int16, UInt16);
  - 32-битные целые (Int32, UInt32);
  - 64-битные целые (Int64);
  - вещественные числа Float32 (single) и Float64 (double);
  - декодирование символа (ASCII / UTF-8);
  - форматированное время Unix Epoch.
- **Поиск**: поиск по шестнадцатеричным байтам (например, `4D 5A`) или текстовым строкам с подсветкой и переходом между совпадениями.
- **Переход по смещению**: `Ctrl+G` с поддержкой шестнадцатеричных (`0x100`, `100h`) и десятичных адресов.
- **Форматы копирования**: копирование выделенных байт как HEX-строка, C-массив (`0x4D, 0x5A, ...`), ASCII, Base64 или адрес смещения.
- **Масштабирование**: увеличение и уменьшение шрифта комбинациями `Ctrl+=` и `Ctrl+-`.
- **Доступность**: открытие любого файла в HEX-просмотрщике через контекстное меню Проводника, меню «Файл» и палитру команд.

### 4. Markdown Viewer (.md)
- Автоматически визуализирует файлы документации с заголовками, таблицами, цитатами и блоками кода.
- Поддерживает переключение в режим исходного кода для быстрого редактирования кнопкой **«Редактировать»**.

# Часть VI. ИИ-агент

## Глава 19. ИИ-агент: провайдеры, контекст и команды

Панель **«ИИ-агент»** открывается значком ✦ на панели активности или по **`Ctrl + Shift + I`**. Это встроенный чат, который видит ваш проект и может править код прямо в редакторе.

### Подключение модели

Настройки → **ИИ-агент**. Поддерживаются провайдеры: DeepSeek, OpenAI, Claude (Anthropic), Google Gemini, opencode zen, OpenRouter, Groq, а также локальные Ollama и LM Studio (им ключ не нужен).

- Ключ хранится **отдельно для каждого провайдера**: переключение между ними больше не затирает ранее введённый ключ.
- Кнопка **«Получить ключ…»** открывает страницу выдачи ключей выбранного провайдера.
- Кнопка **«Проверить подключение»** делает реальный запрос; при ошибке выводится причина (неверный ключ, нет средств, тайм-аут), а не голый код ошибки.
- **Лимита токенов больше нет.** PyScribe не отправляет `max_tokens` вовсе — модель отвечает столько, сколько нужно. Поле «Лимит токенов ответа» можно оставить на «без ограничения»; значение больше 8192 отправляется как явный бюджет. Если провайдер всё же оборвёт ответ на своём потолке, агент автоматически продолжит его.

### Уровень размышлений

Сколько модель «думает» перед ответом, задаётся в трёх местах:

- кнопка **«Мысли: …»** в панели ввода (Авто / Без размышлений / Низкий / Средний / Высокий);
- **Настройки → ИИ-агент → «Уровень размышлений»**;
- команда **`/reasoning auto|none|low|medium|high`**.

Для OpenAI-совместимых API отправляется `reasoning_effort`, для Claude — `thinking` с бюджетом (temperature при этом = 1). Если сервер не понимает параметр, запрос автоматически повторяется без него, так что ответ всё равно придёт.

### Как работает агент

Агент — не «чат с одним ответом», а полноценный цикл с инструментами:

1. Модель может сколько угодно раз читать файлы, искать по проекту, править их и запускать команды — цикл останавливается только когда она выдаст финальный ответ (или вы нажмёте «Стоп» / Esc).
2. Результаты инструментов передаются **целиком**, без обрезки: прочитанный файл модель видит от начала до конца. Большие файлы можно читать частями (`offset`/`limit`).
3. Если модель повторяет один и тот же вызов, результат переиспользуется, а ей сообщается «уже вызывалось — продолжай», поэтому агент не крутится на месте.
4. Временные сбои провайдера (429, 5xx, обрыв соединения) повторяются автоматически с паузой.
5. В строке **«Готово»** видно, сколько инструментов вызвано и сколько токенов потрачено (включая попадания в кэш).

### Контекст и кэш

| Режим | Что отправляется |
| :--- | :--- |
| **Без контекста** | только ваш вопрос (независимый запрос) |
| **Текущий файл** | содержимое открытого файла и выделение |
| **Проект** | компактная карта проекта (папки и число файлов в них) |

Отдельный файл можно прикрепить точечно: наберите **`@`** и выберите файл из проекта — он уйдёт **целиком**. Содержимое @-файлов кэшируется по времени изменения: повторный запрос не перечитывает диск, а изменённый файл читается заново. История диалога сохраняется в `<проект>/.pyscribe/ai_chat.json` и восстанавливается при следующем открытии проекта; `/clear` начинает новый диалог и удаляет сохранение.

Выбор **эксклюзивный** — активен ровно один режим. При открытии проекта контекст сам переключается на «Проект», при закрытии — на «Без контекста»; вручную выбранный «Текущий файл» при этом не сбрасывается.

Отдельный файл можно прикрепить точечно: наберите **`@`** и выберите файл из проекта.

### Команды чата

Начните сообщение со **`/`** — откроется список команд с автодополнением:

| Команда | Назначение |
| :--- | :--- |
| `/help` | список всех команд |
| `/model [имя]` | показать или сменить модель |
| `/models` | запросить список моделей у провайдера |
| `/provider [ключ]` | сменить провайдера |
| `/free` | показать бесплатные модели |

| `/mode solve\|teach` | режим агента (см. главу 20) |
| `/reasoning auto\|none\|low\|medium\|high` | уровень размышлений модели |

### Работа с ответом

- Ответ приходит потоком; во время генерации виден индикатор «Думает…» со счётчиком размышлений. После ответа **размышления удаляются** — в чате остаётся только результат.
- **Очередь сообщений.** Если отправить вопрос во время генерации, он не потеряется: встанет в очередь (появится чип «В очереди сообщений: N») и отправится автоматически.
- **`Esc`** останавливает генерацию; кнопка «Стоп» делает то же.
- Правый клик по панели открывает действия: повторить запрос, скопировать ответ, применить код, экспортировать диалог в Markdown, очистить очередь, новый диалог, настройки.
- MCP-инструменты: если подключены серверы, вызовы видны в чате строкой «Инструмент: …».

## Глава 20. Сократический режим и уровни строгости

Обычный ИИ-ассистент решает задачу за вас: выдаёт готовый код, вы копируете его и не учитесь. **Сократический режим** переворачивает это: агент становится наставником, который ведёт вас к решению вопросами и подсказками, но **не отдаёт готовый ответ**.

Режим предназначен для обучения — например, при подготовке к защите лабораторных и дипломной работы.

### Как включить

Режим переключается **командой в чате** (отдельной кнопки в поле ввода нет):

- **`/mode teach`** — включить наставника;
- **`/mode solve`** — вернуться к обычному режиму;
- **`/mode`** без аргумента — показать текущий режим;
- **`/strictness soft|normal|strict`** — выбрать строгость наставника;
- продублировать настройку можно в меню **Настройки → ИИ-агент → «Режим агента»**.

В режиме «Наставник» в шапке панели появляется бейдж **«наставник · обычный»** — он показывает и уровень строгости.

### Как агент себя ведёт

Правила наставника:

1. **Никогда** не выдаёт готовый код решения и не переписывает ваш код целиком.
2. Задаёт **не более одного вопроса** за сообщение, и этот вопрос — последняя строка ответа.
3. Ведёт по лестнице подсказок, не перескакивая шаги:
   - шаг 1 — где искать (файл, условие, функция);
   - шаг 2 — какая концепция или правило языка здесь работают;
   - шаг 3 — короткий фрагмент в пределах лимита строгости;
   - шаг 4 — только после двух неудачных попыток — полное решение с разбором.
4. Если вы ошиблись — не исправляет молча, а спрашивает, что произойдёт в вашем варианте.
5. Если вы рассуждаете верно — подтверждает, что именно верно, и углубляет вопрос на шаг.
6. Если вы **дважды подряд** прямо просите готовый ответ — выдаёт его, но обязательно с разбором: почему работает и что было не так.

### Уровни строгости

Не всем нужен одинаково суровый наставник. Уровень задаётся командой **`/strictness …`** или в настройках, а текущий уровень виден в бейдже рядом с заголовком панели.

| Уровень | Сколько кода можно | Кому подходит |
| :--- | :--- | :--- |
| **Мягкий** (`soft`) | до 5 строк в примере | когда без примера объяснение буксует |
| **Обычный** (`normal`, по умолчанию) | до 3 строк, только как иллюстрация | повседневное обучение |
| **Строгий** (`strict`) | **ноль** — только словами | подготовка к защите, экзамен, отработка теории |

Пример разницы на вопросе «как удалить дубликаты из списка?»:

- **Мягкий** — короткий пример на 3–5 строк плюс объяснение и вопрос.
- **Обычный** — объяснение словами, максимум фрагмент на 2–3 строки.
- **Строгий** — только словами: какие структуры и методы существуют и чем они различаются, без единой строки кода.

Уровень строгости действует **только** в режиме «Наставник»; в режиме «Решение» он не влияет ни на что, поэтому в меню пункт недоступен.

### Гарантия, что ответ не сорвётся в код

Модель может проигнорировать инструкцию. Поэтому режим защищён на уровне приложения:

1. Если в ответе появился блок кода длиннее разрешённого уровня — PyScribe **просит модель переписать** ответ по правилам.
2. Если модель повторила нарушение — длинный блок **скрывается** и заменяется пометкой «(фрагмент решения скрыт в режиме наставника)», а в конце добавляется вопрос «Какая часть этого фрагмента тебе непонятна?».

Таким образом, даже при сбое модели вы не получите готовое решение, а останетесь в диалоге.

### Практический сценарий

1. Включите «Наставник» и уровень **«Строгий»**.
2. Откройте файл с ошибкой, включите контекст «Текущий файл».
3. Спросите: «Почему функция падает на пустом списке?»
4. Отвечайте на вопросы агента своими рассуждениями. Ошибки он не исправит — но покажет, где вы свернули не туда.
5. Снизьте строгость до «Мягкий», если нужен пример синтаксиса.
6. Когда поймёте причину — вернитесь в режим «Решение» и попросите применить исправление.

### Частые вопросы

**Агент задаёт вопрос вместо ответа, это ошибка?** Нет, это и есть режим наставника. Переключитесь на «Решение» (`/mode solve`), если нужен готовый код.

**Можно ли получить код совсем?** Да: дважды подряд попросите готовый ответ — режим это разрешает, но добавит разбор.

**Где посмотреть текущий режим и строгость?** Бейдж в шапке панели и подпись кнопки режима; также команды `/mode` и `/strictness` без аргументов.

**Сохраняется ли выбор?** Да, оба параметра хранятся в настройках и восстанавливаются при следующем запуске.

### Инструменты агента: файлы, терминал, приложения

Агент не только отвечает текстом — он может **работать с проектом** через инструменты, как в DeepSeek Harness:

| Инструмент | Что делает | Подтверждение |
| :--- | :--- | :--- |
| `read_file` | читает файл проекта (можно частями: `offset`/`limit`) | не требуется |
| `list_directory` | показывает содержимое папки | не требуется |
| `search_in_project` | ищет текст по файлам проекта | не требуется |
| `write_file` | создаёт или перезаписывает файл | только в ограниченных режимах |
| `run_terminal_command` | выполняет команду в проекте | только в ограниченных режимах |
| `open_application` | запускает приложение/утилиту | только в ограниченных режимах |

- Все пути ограничены **корнем открытого проекта**: выйти за его пределы агент не может.
- Режим **«Полный доступ»** работает **без диалогов**: агент читает, правит файлы и выполняет команды сразу — это и есть режим «сделай сам». Ограниченные режимы («Только чтение», «Только запись») по-прежнему спрашивают подтверждение перед изменением файла или командой.
- Пока запрос выполняется, внизу чата видна **одна живая строка** с текущим инструментом (`› read_file · lib/parser.py`); она обновляется на каждом шаге и **исчезает после ответа**. В истории остаются только вопросы и объяснения — никаких строк инструментов, JSON и служебного текста.
- Отключить опасные инструменты можно в **Настройки → ИИ-агент → Инструменты агента**: «Разрешить агенту изменять файлы» и «Разрешить команды в терминале».

Пример: «прочитай `core/app.py`, найди ошибку в `parse()` и исправь» — агент прочитает файл, сам внесёт правку через `write_file` и в ответе коротко объяснит, что изменено и как проверить.

Агент работает **кодом, а не текстом**: в чат он пишет только краткое объяснение (обычно 3–6 строк), а сами изменения вносит в файлы проекта.

### Оформление чата

Ответы ассистента — плоский текст с заголовками, списками и таблицами:

- шрифт чата **крупнее интерфейса** и масштабируется вместе с «Масштабом интерфейса»: базовый размер берётся из «Размера шрифта интерфейса» +2 px, но не меньше 16 px;
- **поле ввода, сообщения пользователя и блоки кода** набраны тем же размером, что и ответы (16 px); чипы контекста/модели — 13 px, служебные строки (инструменты, метрики) — 13 px;
- каждый абзац отделён отступом и имеет увеличенный межстрочный интервал (1.65) — текст не слипается;
- **списки** получили висячий отступ: перенесённые строки начинаются под текстом пункта, а не под его номером;
- строка, целиком набранная жирным, показывается как подзаголовок;
- под полем ввода — **строка метрик сессии**, как в DeepSeek Harness: `N отв. · M шагов · T tok/s · K tok · кэш %`;
- рассуждения модели и служебные фразы вроде «Читаю файл, проверяю…» **в ответ не попадают**: в чате остаётся только финальный ответ;
- **таблицы**: приглушённая шапка с фоном, равные колонки, вертикальное выравнивание по верху и чёткие разделители строк; код внутри ячеек — обычный моноширинный без «плашек», иначе таблица превращалась в стену серых блоков;
- **встроенный код** (`items[::-1]`) подсвечивается моноширинным шрифтом в скруглённой плашке;
- **блоки кода** рендерятся настоящим ядром редактора: тот же шрифт, та же подсветка синтаксиса, что и в `QCodeEditor`, с заголовком языка и кнопкой **«Копировать»**;
- длинные блоки ограничены по высоте и прокручиваются;
- сообщения пользователя — компактные пузыри справа;
- при наведении на ответ доступны **«Копировать»** и **«Повторить»**.

# Часть VII. Автоматизированное тестирование

## Глава 21. «Адвокат дьявола»: поиск багов граничными входами

Обычные тесты запускают код на тех данных, которые придумал человек. А «Адвокат дьявола» **сам** подбирает входы, на которых функция ломается, и доказывает падение минимальным примером.

Инструмент живёт на вкладке **«Испытания»** панели анализа или запускается командой `adversary` из палитры команд (`Ctrl + Shift + P`).

### Как это работает

1. **Генерация входов.** Для каждой функции верхнего уровня берутся параметры и подбираются граничные значения:
   - если есть **аннотации типов** — по типу (`int`, `str`, `list`, `dict`, `Optional` и т. д.);
   - если аннотаций нет — PyScribe выводит тип из тела функции: `items[0]` → последовательность, `x / 2` → число, `text.split()` → строка, `mapping.items()` → словарь;
   - совсем неизвестные параметры получают типовой набор (`[]`, `""`, `0`, `{}`, `-1`, `None`, длинная строка).

2. **Изолированный запуск.** Каждый случай выполняется в **отдельном процессе** с таймаутом. Поэтому падение не уронит IDE, а зависание (`while True`) будет поймано по таймауту и показано как «зависание».

3. **Минимизация.** Если вход из 500 элементов падает, PyScribe методом **delta-debugging** сокращает его до минимального воспроизводящего: убирает половину, потом ещё половину, и так пока падение сохраняется.

4. **Результат.** В таблице по каждой находке: функция, минимальный вход, тип ошибки, номер строки. Двойной клик переходит к проблемной строке в редакторе.

### Пример

Функция:

```python
def head(items):
    return items[0]
```

Результат испытания: `head([])` → `IndexError: list index out of range`, строка 2. Правильный вопрос «а что если список пуст?» инструмент задал сам.

### Почему это не «ещё один линтер»

| Инструмент | Что делает | Чего не делает |
| :--- | :--- | :--- |
| Hypothesis (библиотека) | генерирует входы | не работает как часть IDE, не чинит и не объясняет |
| Отладчик | выполняет ваш сценарий | вход придумывает человек |
| ИИ-ревью | рассуждает о коде | **не исполняет** код, поэтому говорит «возможно, баг» |

Здесь результат **доказуем**: есть вход, есть падение, есть номер строки.

### Кнопки

- **«Испытать»** — запустить проверку текущего файла (работает в фоне, интерфейс не замерзает).
- **«Создать тест»** — сохранить найденные падения как **pytest-тесты**; они сразу воспроизводят баги и остаются защитой от повторного появления.
- **«Экспорт»** — отчёт в Markdown для отчёта или диплома.
- **«Спросить ИИ»** — отправить находку ИИ-агенту: он объяснит причину и предложит исправление.

### Ограничения

- Проверяются **функции верхнего уровня**; методы классов не вызываются (для них нужен экземпляр, а его создание может иметь побочные эффекты).
- Асинхронные функции пропускаются: для них нужен событийный цикл.
- Инструмент сообщает только о **падениях и зависаниях**. Неверный, но не падающий результат требует «оракула» — ожидаемого значения, которого у инструмента нет.
- Код проекта исполняется реально: используйте инструмент на своём коде, а не на недоверенном.

### Порядок работы

1. Откройте файл с функцией — вкладка сама подхватит файл из активного редактора.
2. Панель анализа → вкладка **«Испытания»** → «Испытать» (или команда `adversary`).
3. Изучите найденные падения, двойным кликом перейдите к строке.
4. Нажмите «Спросить ИИ», чтобы получить объяснение и варианты исправления.
5. Нажмите «Создать тест» — сохраните регрессионные тесты, чтобы баг не вернулся.

## Глава 22. Диспетчер задач проекта

Анализ отвечает на вопрос «что не так», но работу двигают задачи. Вкладка **«Задачи»** в панели анализа — это доска проекта: список того, что нужно сделать, со статусом, приоритетом и привязкой к файлу.

### Зачем она нужна

- Рекомендации анализатора превращаются в конкретные задачи одним нажатием.
- Список переживает перезапуск и хранится рядом с кодом — в `.pyscribe/tasks.json`, поэтому его можно закоммитить вместе с проектом.
- Видно, что сделано и что ещё нет, без внешних трекеров.

### Как пользоваться

1. Панель анализа → вкладка **«Задачи»**.
2. **«Новая»** — добавить задачу вручную.
3. **«Из рекомендации»** — создать задачу из выбранной строки на вкладке «Советы» (подставится файл, строка и описание).
4. Выберите задачу и нажмите **«Готово»**, **«В работу»**, **«Удалить»** или **«Очистить готовые»**.
5. Двойной щелчок по задаче с привязанным файлом открывает этот файл на нужной строке.
6. Название задачи можно переименовать прямо в списке: двойной щелчок по имени.

### Статусы и приоритеты

| Статус | Значение |
| :--- | :--- |
| **К выполнению** | задача заведена, работа не начата |
| **В работе** | задача в текущем фокусе |
| **Готово** | задача выполнена (выполненные зачёркнуты) |

Приоритеты: высокий, средний, низкий. В списке сначала идут задачи «в работе», затем «к выполнению», затем выполненные; внутри — по приоритету.

Фильтр над списком переключает отображение между всеми задачами и конкретным статусом.

## Глава 23. Обновления PyScribe и интеграция с проводником Windows

### Проверка обновлений

PyScribe сверяет свою версию с последним релизом на
[github.com/stand4r/PyScribe](https://github.com/stand4r/PyScribe/releases):

- **«Справка → Проверить обновления…»** — ручная проверка в любой момент;
- **автоматически** — один раз в сутки при запуске, если включена настройка
  **Настройки → Система → «Проверять обновления автоматически при запуске»**;
- кнопка **«Проверить обновления»** есть и в окне **«Справка → О программе»**.

Окно обновления показывает установленную и доступную версии и список изменений.
Дальше всё делается одной кнопкой:

| Как запущен PyScribe | Что делает обновление |
| :--- | :--- |
| из исходников (есть `.git`, нет локальных правок) | `git pull --ff-only`, затем предложение перезапустить |
| установленная сборка (`PyScribe.exe`) | скачивает `PyScribe-Setup-vX.Y.Z.exe`, проверяет SHA-256, запускает установщик; он закрывает и снова открывает PyScribe |
| локальные правки в исходниках | обновление через git недоступно — открывается страница релиза |

Если сеть недоступна или GitHub ограничил частоту запросов, окно честно
показывает причину и кнопку **«Повторить»**. Версия хранится в файле
[VERSION](VERSION); при выпуске нового релиза её нужно поднять — по ней
сравниваются версии.

### «Открыть с помощью» и контекстное меню проводника

PyScribe умеет открывать файлы и папки прямо из проводника Windows:

1. **Настройки → Система → Проводник Windows** — включите
   **«Добавить «Открыть в PyScribe» в контекстное меню файлов и папок»**.
   То же самое доступно в меню **«Справка → Интеграция с проводником…»**.
2. После включения:
   - в контекстном меню любого файла и папки появляется **«Открыть в PyScribe»**;
   - PyScribe появляется в системном окне **«Открыть с помощью»** (для
     поддерживаемых расширений и для файлов без ассоциации);
   - файл открывается в редакторе, папка — как проект (без диалога выбора
     анализаторов);
   - если PyScribe уже запущен, файл откроется в текущем окне — второй процесс
     не создаётся.
3. Выключите флажок, чтобы удалить записи. Права администратора не нужны: всё
   хранится в `HKEY_CURRENT_USER\Software\Classes`, установщик добавляет те же
   записи при установке и удаляет их при удалении PyScribe.

## Приложение Б. Формулы и шкалы архитектурных метрик

### 1. Цикломатическая сложность (Cyclomatic Complexity, CC)
Вычисляется по графу потока управления метода:
$$CC = E - N + 2P$$
где:
- $E$ — число рёбер графа (переходов между блоками).
- $N$ — число вершин графа (базовых блоков кода).
- $P$ — число связных компонент (обычно 1 для одной функции).

**Шкала интерпретации:**
- `1 – 5`: Простой, ясный метод с минимальным риском ошибок.
- `6 – 10`: Умеренная сложность, легко поддаётся модульному тестированию.
- `11 – 20`: Высокая сложность, рекомендуется рефакторинг и декомпозиция.
- `> 20`: Критическая сложность, высокий риск дефектов при модификации.

### 2. Индекс сопровождаемости (Maintainability Index, MI)
$$MI = \max\left(0, \frac{171 - 5.2 \ln(V) - 0.23 \cdot CC - 16.2 \ln(LOC)}{171} \cdot 100\right)$$
где $V$ — объём Холстеда, $CC$ — цикломатическая сложность, $LOC$ — число строк кода.

## Приложение В. Руководство по сборке .exe и установщика

PyScribe v1.0.2 поставляется с полностью обновлённым и настроенным конвейером компиляции под 64-битные системы Windows.

```
  Исходный код PyScribe
         │
         ▼ (build_exe.bat / PyScribe.spec)
  dist\PyScribe\ (Автономный дистрибутив с PyScribe.exe и _internal)
         │
         ▼ (installer\build_installer.bat / PyScribe.iss)
  installer_output\PyScribe-Setup-v1.0.2.exe (Полноценный инсталлятор)
```

### Шаг 1. Сборка автономного исполняемого пакета (EXE)
1. Откройте терминал в корневой папке проекта.
2. Запустите командный файл:
   ```cmd
   build_exe.bat
   ```
3. Скрипт проверит окружение, установит PyInstaller, подключит спецификацию [PyScribe.spec](file:///c:/Users/Dmitr/Downloads/PyScribe-Project-Intelligence-v1.0.2-ui-fix9-download/PyScribe-v1.0.2/PyScribe.spec), упакует все модули, темы и документацию в каталог `dist\PyScribe\`.
4. Полученный исполняемый файл `PyScribe.exe` запускается в оконном режиме (без всплывающего черного консольного окна) и **не требует наличия установленного Python на целевом компьютере**.

### Шаг 2. Сборка дистрибутива-установщика (Inno Setup)
1. Убедитесь, что на компьютере установлен **Inno Setup 6** (бесплатная программа сборки инсталляторов).
2. Перед выпуском поднимите номер версии в файле [VERSION](VERSION) (например, `1.2.0`). Это единственное место: диалог «О программе», установщик и проверка обновлений читают один и тот же файл.
3. Запустите скрипт:
   ```cmd
   installer\build_installer.bat
   ```
4. В каталоге `installer_output\` будет создан файл мастера установки `PyScribe-Setup-v1.2.0.exe` (имя берётся из `VERSION`).
5. Инсталлятор поддерживает установку без прав администратора, русский и английский интерфейсы, создание ярлыков на рабочем столе и меню «Пуск», запись пункта **«Открыть в PyScribe»** в контекстное меню проводника, а также чистое удаление через «Установка и удаление программ».

## Приложение Г. Устранение неполадок и частые вопросы (FAQ)

### 1. Как подготовить проект к публикации на GitHub?
1. В корне проекта настроен файл [.gitignore](file:///c:/Users/Dmitr/Downloads/PyScribe-Project-Intelligence-v1.0.2-ui-fix9-download/PyScribe-v1.0.2/.gitignore), исключающий временные кэши, сессии и каталоги сборки `build/`, `dist/`, `installer_output/`.
2. Если локальный Git-репозиторий ещё не инициализирован, нажмите в панели Git кнопку **«Инициализировать репозиторий»**.
3. Авторизуйтесь на вкладке Git по токену GitHub (PAT) и нажмите кнопку **«Опубликовать проект на GitHub»**. Все исходные файлы и спецификации сборки будут безопасно загружены на ваш серверный аккаунт.

### 2. Почему при запуске Push или Pull не отображались результаты?
В версии 1.0.2 все операции контроля версий снабжены явными информационными модальными диалогами:
- При успешном выполнении Push или Pull среда сообщает имя обновленной ветки и ответ сервера Git.
- При ошибках аутентификации или сетевых сбоях среда выдаёт подробный текст ошибки с рекомендациями по исправлению.
- При попытке создания коммита в чистом репозитории выдаётся предупреждение о том, что изменений нет.

### 3. Как изменить горячие клавиши?
В меню **`Справка` → `Горячие клавиши`** доступна интерактивная таблица всех сочетаний клавиш. Дополнительно их можно сконфигурировать через файл `config/keybindings.json`.
